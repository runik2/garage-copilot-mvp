# Гаражный помощник — локальный MVP

Личное PWA для карточек автомобилей, истории работ и **пошагового руководства по ремонту**: механика, электрика, схемы, диагностика — с привязкой цифр к страницам ваших PDF.

Приложение не обращается к внешним VIN-сервисам и не содержит закрытых ремонтных данных: всё, что показывает раздел «Руководство», — авторские памятки по порядку работ плюс текст из документов, которые вы загрузили сами.

## 1. Краткий план и архитектура

`React PWA → Express API → PostgreSQL`, загруженные оригиналы хранятся в локальной папке `data/uploads`. По умолчанию PostgreSQL работает через PGlite прямо в процессе Node — внешний сервер БД не обязателен. PDF разбирается постранично; текст и номер страницы индексируются PostgreSQL. JWT выдаётся только единственному владельцу, создаваемому миграцией; регистрации нет.

Модули: авторизация, автомобили, работы, источники, PDF-индексация, поиск, рабочий лист, **руководство по ремонту** и **подтверждённые значения**. VIN-декодирование намеренно отсутствует.

## 2. Схема базы данных

- `users 1—N vehicles`: единственный владелец и его автомобили.
- `vehicles 1—N jobs`: заявки и история работ.
- `jobs 1—N job_steps`: шаги, статус, уверенность, источник и страница.
- `users/vehicles 1—N sources`: официальные, открытые и личные источники.
- `sources 1—N source_pages`: извлечённый текст PDF по страницам с GIN-индексом.
- `vehicles 1—N vehicle_notes`: заметки по автомобилю или узлу.
- `vehicles 1—N vehicle_specs`: подтверждённые моменты/объёмы/номиналы со ссылкой на `sources` и номер страницы.

Схема: `db/001_schema.sql`, `db/002_specs.sql`. Миграция применяет все `db/*.sql` по порядку номеров.

## 3. Экраны

1. Приватный вход без регистрации.
2. Рабочий стол: выбор автомобиля и описание задачи.
3. Карточки автомобилей с полной комплектацией.
4. Читаемый пошаговый рабочий лист.
5. История и избранные работы.
6. Источники: импорт PDF/изображений и привязка к автомобилю/узлу.
7. Глобальный поиск по VIN, автомобилям, работам и тексту PDF с номером страницы.
8. **Руководство по ремонту** — см. раздел 6.
9. Печать или сохранение рабочего листа в PDF через системный диалог браузера.

## 5. Запуск

### Вариант А — без Docker (по умолчанию)

PostgreSQL работает внутри Node через PGlite (тот же PostgreSQL, собранный в WASM). Docker и установка сервера БД не нужны.

```powershell
cd C:\Users\xamma\Desktop\Harness\Codex   # важно: команды выполняются в папке проекта
npm install
npm run db:migrate
npm run dev
```

Откройте `http://localhost:5173`. Вход — `ADMIN_EMAIL` и `ADMIN_PASSWORD` из `.env`.

Если файла `.env` нет, скопируйте `.env.example` → `.env`, задайте `JWT_SECRET` и `ADMIN_PASSWORD` и повторите `npm run db:migrate`.

Файл базы лежит в `data/pgdata` (в git не попадает). С одной папкой базы должен работать только один процесс API: не запускайте второй `node server/index.js`.

Начать с нуля: остановить API, удалить `data/pgdata`, снова `npm run db:migrate`.

### Вариант Б — обычный PostgreSQL (Docker или локальная установка)

```powershell
Copy-Item .env.example .env
# в .env закомментируйте DB_MODE/PGLITE_DIR и раскомментируйте DATABASE_URL
docker compose up -d
npm install
npm run db:migrate
npm run dev
```

Проверки перед коммитом:

```powershell
npm run content:check   # структура контент-паков и геометрия схем
npm run preview:render  # SSR-рендер схем и экранов + валидация разметки
npm run build           # production-сборка
```

`preview:render` кладёт готовые HTML в `public/preview/` — их можно открыть в браузере, чтобы посмотреть все схемы без запуска приложения.

## 6. Руководство по ремонту

Вы заходите, выбираете автомобиль (марка + модель), и слева появляется список процедур по системам: двигатель, тормоза, трансмиссия, **ходовая часть**, **электрика**, обслуживание. Процедура открывается как пошаговая памятка.

Каталог знает **151 модель 37 марок** ([catalog.ts](src/manuals/catalog.ts)) — от LADA Granta и Kia Rio до Haval Jolion и Mercedes-Benz E-Class. Для каждой записи хранятся поколения, кузов, алиасы («Камри», «ВАЗ 2190», «Мерседес» — узнаются) и ссылки на официальные порталы документации производителя.

Что внутри процедуры:

- вступление, инструмент, материалы, детали;
- шаги с мерами предосторожности, подсказками по инструменту и проверками после шага;
- SVG-схемы: электрические цепи, выноски к узлам, алгоритмы диагностики, порядок затяжки;
- коды неисправностей по теме с ориентировочными причинами;
- поиск по вашим загруженным PDF и открытие нужной страницы рядом с шагом.

Покрытие при любом выборе: 15 универсальных процедур (масло, тормоза, ГРМ, охлаждение, форсунки, стойки, шаровые, рулевые тяги, ступица, втулки, диагностика ДВС, электрика, разряд АКБ, регламент ТО) плюс 15 процедур пакета Kia Ceed CD. Процедуры описывают **порядок работ**, а цифры приходят из ваших документов.

### Массовый импорт документации

Когда документы у вас на руках (купленная подписка erWin/TIS, официальные руководства владельца, свои сканы):

```powershell
npm run sources:import -- "D:\Manuals" --dry-run   # проверить распознавание
npm run sources:import -- "D:\Manuals"             # загрузить и проиндексировать
```

Скрипт [import-sources.mjs](scripts/import-sources.mjs) рекурсивно обходит папку, определяет марку/модель/год по имени файла («Kia Ceed 2019.pdf»), создаёт карточки автомобилей, разбирает каждый PDF постранично и индексирует текст. Дальше эти страницы подставляются к шагам руководства и ищутся поиском.

Скачивать чужие руководства из интернета приложение не умеет и не будет: это нарушение авторских прав. Ссылки на официальные порталы даны в интерфейсе — платная подписка там законна, обход оплаты не реализован.

### Почему цифры не в контент-паке

Моменты затяжки, объёмы и номиналы предохранителей зависят от комплектации, поэтому в памятках их нет — вместо числа стоит **слот спецификации**:

1. Шаг помечен «Момент затяжки сливной пробки — значения нет».
2. Вы нажимаете «Найти в источниках» → приложение ищет по тексту ваших PDF.
3. Находите страницу, вписываете значение так, как оно напечатано в документе.
4. Слот становится зелёным: значение + название источника + номер страницы. Оно же появляется во всех остальных шагах и в других автомобилях не «протекает» — привязка идёт к `vehicle_id`.

Это компромисс между «всё есть» и «ничего не выдумано»: руководство получается полным, но каждая цифра имеет источник.

### Как добавить свою марку

1. Скопируйте `src/manuals/kia/` → `src/manuals/<marka>/` и поправьте данные: `id`, `title`, `system`, `steps`, `keywords`.
2. Схемы описываются данными в `src/manuals/diagramSpecs.ts` (`schematic` / `part` / `flow` / `torque`) — рисовать SVG вручную не нужно.
3. Подключите пак в `src/manuals/index.ts` (массив `PACKS`).
4. Запустите `npm run content:check` — он поймает битые ссылки на схемы, дубли id, выноски за границей холста и числа с единицами измерения (их в тексте быть не должно).

Если для модели пака нет, приложение честно показывает универсальные памятки, данные каталога и предупреждение, а не подставляет чужую инструкцию.

## 7. Правила источников и безопасности

- Загружайте только материалы, которые вправе использовать. Обход paywall, DRM и авторизации не реализован.
- Авторские памятки и схемы объясняют порядок работ и логику цепи, но не являются официальной ремонтной инструкцией и не заменяют руководство производителя.
- Моменты затяжки, объёмы и интервалы не генерируются: до привязки источника приложение прямо пишет, что данных нет.
- Для опасных работ всегда показывается требование окончательной проверки по официальному руководству конкретной комплектации.
- Демо-карточки появляются только по отдельной кнопке и явно помечены.
